# CONTEXT

## Overview

Reverse proxy in front of the NVIDIA NIM API. Clients address the proxy exactly as if it were the
upstream API — same paths, same bodies, same response shapes — but authenticate with a
caller-controlled token instead of the real key. Two credentials, one per direction of trust:
clients hold the proxy token; the proxy alone holds the API key.

The proxy is a **transparent drop-in**: any OpenAI-compatible client can point at it without code
changes. Transparency also means the proxy never reveals what is behind it — upstream identities
and failure details are scrubbed from every locally generated response.

## Glossary

| Term | Definition |
| --- | --- |
| Client | Application calling the proxy. Authenticates with the proxy token. Never sees the API key. |
| Upstream | Remote API the proxy forwards requests to (NVIDIA NIM in deployment; any base URL in configuration). |
| Base URL | Upstream anchor URL. Every proxied path is appended onto it; any API-version segment it carries is ignored during mapping. |
| API key | Real NVIDIA credential. Lives server-side only; inserted into the upstream request's authorization header. |
| Proxy token | Client-facing credential. The sole authentication for proxied calls; compared in constant time. |
| Credential swap | Replacing the client's bearer credential with the API key on the upstream request. The client's own credential never reaches upstream. |
| Unconfigured | Proxy is running but the API key or proxy token is missing (whitespace counts as missing). Degrades to a "not configured" status response; never crashes. |
| Misconfigured | Invalid or missing base URL. The proxy refuses to start rather than come up half-working. |
| Health | Self-report distinguishing healthy from unconfigured. The only endpoint that needs no authentication. |
| Pass-through | Upstream response forwarded byte-for-byte with headers preserved per fidelity rules. The normal case for successful calls. |
| Local response | Status and body generated by the proxy itself: unauthenticated, unknown path, unconfigured, upstream failure. Never includes upstream details such as hostnames or URLs. |
| Upstream failure | Upstream unreachable or errored. Surfaced to the client as a generic gateway error. |
| Path mapping | Forwarding rule: the client's `/v1/...` path and query are appended verbatim to the base URL. A bare version prefix with no resource is an unknown path. |
| Header fidelity | Principle that headers arrive at each hop as the sender intended: multi-value headers stay multi-value, hop-by-hop headers are stripped both ways, and body length is preserved wherever the body is untouched. |
| Response stream | Unbuffered upstream body flowing chunk-by-chunk to the client. Active streams are never cut; silence is bounded. |
| Connect window | Maximum wait for the upstream to begin responding. Bounds the pre-response phase only. |
| Idle window | Maximum silence tolerated inside an active response stream. Resets on every received chunk, so a producing stream is never cut. |
| Grace period | Bounded interval after a shutdown signal during which in-flight streams may finish; idle connections are dropped immediately. |
| OpenAI-compatible client | Consumer speaking the OpenAI chat-completions dialect. The proxy's target interoperability surface. |
| Admission control | Decides whether an authenticated request runs now, must wait, or receives a Local response. Not a budget in itself: the budgets and the concurrency ceiling are the state it decides from. |
| Queue | The bounded FIFO set of authenticated requests waiting for capacity. Not a retry mechanism: a queued request is forwarded once, unchanged, and never replayed. |
| Rate budget | A rolling 60-second allowance for requests per minute, or for estimated and reconciled tokens per minute. Not a lifetime cap: the window rolls, so spent allowance returns. |
| Per-model budget | A rolling 60-second allowance applying only to requests naming an exact configured model ID. Not a fallback: model IDs match case-sensitively, and an omitted field inherits the global allowance rather than denying. |
| Safety margin | A percentage reduction applied to raw RPM and TPM limits before enforcement. Not a correction of estimated usage: it reserves headroom against the limit, because the estimate itself drifts. |
| Usage reconciliation | Replacing a request's estimated token cost with valid actual usage reported by the Upstream. Neither guaranteed nor implemented: absent, invalid, or unavailable usage keeps the estimate, and the proxy reconciles nothing today. |

Admission control, Queue, Rate budget, Per-model budget, and Safety margin name limits this
proxy validates and stores but does not enforce — `PROXY_RPM`, `PROXY_TPM`,
`PROXY_MAX_CONCURRENT_REQUESTS`, `PROXY_MAX_QUEUE_SIZE`, `PROXY_QUEUE_TIMEOUT_SECONDS`,
`PROXY_SAFETY_MARGIN_PCT`, `PROXY_MAX_BUFFERED_BODY_BYTES`, and `PROXY_MODEL_LIMITS_JSON` are
parsed once at startup and nothing reads them afterward. Usage reconciliation has no
implementation at all. Enforcement arrives in later slices of the rate-limiting epic; the
configuration regime is recorded in `docs/adr/0002-config-operational-fail-fast.md`.
