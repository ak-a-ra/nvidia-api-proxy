## Orchestrator decisions (apply these; record any deviation in the report)

### D1 — the model survives a fallback estimate

The ledger's test list says "the fallback path returns model null". Read together with the story
(§2 ADDED: "`estimateCost` returns a `model` field: the `json.model` string when the body is
parseable and names one, or `null` otherwise"), the model is a property of the parsed body, not of
the estimator's structural success. Therefore:

- A body that parses as JSON and names a model returns that model even when the estimator falls
  back. Example: `{"model":"nemotron"}` with no `messages` and no `tools` →
  `parseRequestMetadata` returns `null` → the fallback path → `model` is `"nemotron"`.
- The fallback returns `null` when the body names no model, or does not parse as JSON at all
  (`json` is `null` / unusable).

Rationale: a client that sends a model-naming but structurally unestimable body would otherwise
escape its per-model cap entirely — the "a budget that appears to exist and does not" failure class
this epic exists to close (see the `specs/state.yaml` decision on per-model limits that are
silently dropped).

If you judge D1 wrong, say so in the report and implement your reading — but do not silently
implement the other reading. The reversal is one guard plus one test.

### D2 — the ledger's verify command is vacuous; it must be strengthened

Measured on this tree (2026-10-21):

```
node --test --test-reporter=tap --test-name-pattern '<no such test>' server.test.js
```

exits 0 and prints a file-level line `ok 1 - server.test.js`. The ledger's grep
`^[[:space:]]*ok [0-9]+ -` matches that line, so the gate goes green when **zero** tests match the
pattern. The strengthened form requires a matching test name:

```bash
out=$(node --test --test-reporter=tap --test-name-pattern 'estimateCost returns the model' server.test.js 2>&1); rc=$?; test "$rc" -eq 0 || { printf '%s\n' "$out"; exit "$rc"; }; n=$(printf '%s\n' "$out" | grep -cE '^[[:space:]]*ok [0-9]+ - .*estimateCost returns the model'); test "$n" -ge 1
```

Measured: tests that do not match the pattern are omitted from the TAP output entirely (no
`# SKIP` lines are emitted), so `n` is 0 when nothing matches and ≥ 1 when the new tests run.

Replace task 1's `verify` string in `specs/epics/e04-rate-limiting/e04s05-tasks.yaml` with the
strengthened form, keep the ledger's `status: failing` until it exits 0, and record the change in
the report. Do not touch the other tasks' verify strings.

### D3 — `server.test.js` imports `budget.js` directly

`server.test.js` today imports only Node built-ins. The new block needs
`import { estimateCost } from "./budget.js";`.

Justification: `estimateCost` is already exported, is pure, and reads no environment, no timer,
and no I/O (`budget.js` module header: "No environment read, no timer, no default of its own").
Importing it adds no test seam, no new export, no injection point, and does not affect harness
hermeticity — the `childEnv()` strip applies to spawned children, and this import reads no
environment at all. This differs from the e04s01 decision that unobservable `config.js` fields are
reviewed by eye: that decision covered config fields the proxy never exposes, while the story
explicitly requires the estimator's return shape to be tested, and that shape is unobservable
through the black-box HTTP harness (the proxy never surfaces the model ID).

Record the reasoning in the report.

## Implementation notes

- Compute the model once in `estimateCost` and add it to both return objects. The fallback path
  currently receives only `buffer`; passing the extracted model in is fine, as is spreading it into
  the fallback result. Keep the two return objects' key sets identical apart from the values.
- Extract with a single rule: a non-empty string `model` on the parsed JSON, otherwise `null`.
  `""` is not a model ID. Whitespace is **not** trimmed — the story forbids normalization, and a
  padded model can never match a config key, which is the safe direction.
- The new comment text must describe the estimator's responsibility and stay accurate after task 2
  (when `budget.js` gains the model windows). Suggested shape: the request names the model, the
  estimator carries that name through with the cost so the caller can resolve it against the
  operator's per-model budget, and the estimator prices every model the same way because pricing
  is the operator's configuration.
- Match the file's comment voice: explain the constraint, not the mechanics.
