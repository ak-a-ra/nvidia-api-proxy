## Objective

Create a root-level `admission.js` module that owns all admission state behind one narrow interface.
Do not wire it into `server.js` yet (wiring is task 2). No behavior change to the existing proxy runtime yet.

## Requirements

1. `admission.js` sits at the project root, next to `server.js` and `config.js`. ESM only (`"type": "module"` in `package.json`) — use `import` / `export`, never `require`.
2. Construct it from `limits` (from `config.limits`, containing `maxConcurrentRequests`, `maxQueueSize`, `queueTimeoutSeconds`).
3. Interface design:
   - Export a constructor / factory function, e.g., `createAdmission(limits)`.
   - `acquire()` method: returns either an immediate admission, a pending ticket resolved later, or a rejection.
     - When `limits.maxConcurrentRequests` is `null` (disabled): admits everything immediately, allocates no queue, and starts no timer.
     - When `maxConcurrentRequests` is a positive number:
       - If `active < maxConcurrentRequests` and queue is empty: increments `active`, returns immediate admission with a release callback/handle.
       - If `active >= maxConcurrentRequests` (or queue not empty):
         - If `queue.length >= maxQueueSize`: returns immediate rejection (e.g. `{ admitted: false, reason: "queue_full" }`).
         - Otherwise: enqueues a ticket. The ticket has a timeout timer (`queueTimeoutSeconds * 1000`). If timeout expires before admission, ticket is rejected (e.g. `{ admitted: false, reason: "queue_timeout" }`) and removed from queue.
   - `release()` callback / method:
     - Must be idempotent per admission (use a settled flag on the ticket/admission handle, not a call counter).
     - Decrements active count.
     - If queue has waiters: pops oldest waiter (FIFO), increments active count (or transfers the slot), resolves the waiter with admission and its own release callback.
4. Three invariants live inside this module and nowhere else:
   - Active count never exceeds the ceiling at any observable moment.
   - Release is idempotent per admission (settled flag, never double-decrements).
   - A ticket whose wait timed out is never admitted afterwards.
5. Waiting is strictly event-driven: resolved by `release()` or timeout timer, NEVER by polling (`setInterval` or `while(true)` loops are prohibited).
6. Zero dependencies: Node built-ins only.
7. `server.js` must NOT re-export limiter internals (issue #13 story 138) and no second test seam may appear (story 139).
8. This task adds no new environment variable: do NOT touch `CONFIG_ENV_VARS` in `server.test.js`.
