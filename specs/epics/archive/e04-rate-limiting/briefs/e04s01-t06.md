# Task brief — e04s01 / task 6: a whitespace-only operational value is absent, not a number

> Source of requirements: `specs/epics/e04-rate-limiting/e04s01-tasks.yaml` task 6,
> `specs/epics/e04-rate-limiting/e04s01-config-owner-and-bind-host.md` §12 first bullet and §11,
> plus the decisions already recorded in `specs/state.yaml` and `LOG.md`. Where this brief and the
> story disagree, the story wins and the deviation is reported — do not silently pick one.

## Objective

`Number("  ")` is `0`, and `0` is a legal value for two of the four task-4 operational
variables: it disables `PROXY_MAX_CONCURRENT_REQUESTS` and it is the low end of
`PROXY_SAFETY_MARGIN_PCT`'s 0-50 range. So a whitespace-only value that reached the numeric
guard would read as a *supplied* value of `0`, which is exactly the "silently disable a budget"
failure the story names in §12.

Task 6 proves the blank check precedes numeric parsing, for all four variables, in a test whose
name is falsifiable against task 4's existing coverage.

## Current state — read this before writing anything

`config.js` **already implements the behavior.** `readLimits` computes
`Boolean(rawConcurrency?.trim())` and the same for queue size, queue timeout, margin, and the
buffered-body ceiling, and only calls `readPositiveInteger` when the corresponding flag is true.
`readRateLimit` and `readModelLimits` do the same. There is nothing to fix in `config.js` unless
you find a path where a whitespace-only value reaches a numeric guard.

Your job is therefore **almost entirely tests plus a proof that the gate is a gate.** Report
that finding honestly in your report — do not manufacture a `config.js` change to look
productive.

## Requirements

1. **Add tests whose names contain the word `whitespace` and the name of at least one of task 4's
   four variables.** The verify command greps passing TAP lines for both, so a test named
   "blank" does not satisfy it. Cover **all four** variables, not just one:

   - `PROXY_MAX_CONCURRENT_REQUESTS`
   - `PROXY_MAX_QUEUE_SIZE`
   - `PROXY_QUEUE_TIMEOUT_SECONDS`
   - `PROXY_SAFETY_MARGIN_PCT`

   A rate-pair test does **not** satisfy requirement 1 and does not count toward the four.

2. **Each whitespace-only value must start the proxy and serve `/health` 200.** Use the blank
   shapes task 4 already established: `""`, `"   "`, `" \t "`. Follow the shape of the existing
   test `PROXY_MAX_CONCURRENT_REQUESTS blank (spaces or tab) starts and serves /health`
   (`server.test.js:1058`) — a `for` loop over the blank shapes, a fresh `withProxy` per
   iteration, and the assertion message naming the shape it failed on.

3. **The distinction that makes the test worth writing: whitespace must be absent, not `0`.**
   `server.test.js:1046` proves `PROXY_MAX_CONCURRENT_REQUESTS=0` starts, and `:1023` proves the
   margin's `0` starts. Both already pass, so "whitespace starts" alone proves nothing about
   *which* branch was taken — the config object is invisible to the child-process harness. Two
   things make the new tests falsifiable rather than decorative:

   - **Cover the two variables where `0` is fatal.** For `PROXY_MAX_QUEUE_SIZE` and
     `PROXY_QUEUE_TIMEOUT_SECONDS`, whitespace-only must start while `0` exits 1 (the existing
     zero test at `:1084` pins the fatal half). If whitespace were parsed as a number those
     variables would exit 1 and the new tests fail. Name both variables in those test names.
   - **State the limit of what is proven in a comment**, as task 4's comment above the blank test
     already does: the harness cannot observe whether whitespace reached the same internal state
     as `0`, and no test may claim it does. What the suite proves is that a whitespace-only
     value takes the *absent* path on the two variables whose `0` is fatal.

4. **`PROXY_SAFETY_MARGIN_PCT` boundary stays pinned.** Whitespace for the margin must start,
   and the existing boundary test at `:1023` continues to pin `0` and `50` as valid and `:51` as
   fatal. Do not weaken either.

5. **The verify's static half checks `config.js` still guards blankness before parsing.** It
   greps for `trim()`. That check passes today. Do not remove or reword the blank checks to make
   anything else pass.

## Harness notes

- `withProxy` merges `proxyEnv` over `process.env`. Passing `undefined` drops the key entirely,
  which is the absent case; passing nothing pins the author's shell. Pass the variable
  explicitly in every new test.
- `runProxyOnce` is the fatal-case seam. If you need it, pass a valid `NVIDIA_BASE_URL` and both
  credentials (`BASE_ENV` at `:955` is the existing shape) so an exit 1 proves your guard and not
  an unrelated missing variable.
- **Known open hazard, not this task's problem to fix:** the suite is not hermetic against
  ambient env. An exported `PROXY_SAFETY_MARGIN_PCT=51` leaves 14 passing and an exported
  `PROXY_RPM=5` leaves 11. Run `npm test` in a clean shell, and if you see a count far below 75,
  that is the cause — report it, do not work around it in this task. Task 11 owns the
  story-level decision.

## Verify


**Prove the gate is a gate.** A check that has only ever run green is not a check. Two mutations,

2. If the whitespace tests pass with the blank check deleted, the tests are decorative — report
