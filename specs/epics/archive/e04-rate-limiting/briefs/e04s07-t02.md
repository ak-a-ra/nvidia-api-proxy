## Task 1 interface available

```js
JSON_OBSERVATION_BYTE_BOUND = 1048576
createJsonObserver(onUsage) -> { observe(chunk), end(), detach() }
usageTotalFromUsage(usage) -> number | null
```

`createJsonObserver` behavior:

- retains raw response bytes up to and including 1,048,576 bytes;
- drops the copy and detaches before retaining a chunk that would exceed the bound;
- `observe(chunk)` never throws and is inert after `end()` or `detach()`;
- `end()` parses the retained body once and delivers `onUsage(total | null)` exactly once;
- `detach()` drops the copy and delivers `onUsage(null)` exactly once if no outcome was delivered;
- callback failures are contained.

behavior impossible. If that occurs, report the blocker before changing the observer contract.

## Requirements

### 1. Eligibility

Compute JSON-observation eligibility from request-time state:

```js
isJson = budget.enabled && Boolean(budgetReservation) && !isSse && Boolean(upstream.body)
```

Observation is content-type agnostic. Do not require `application/json`, and do not inspect the
response `content-type` to decide eligibility.

### 2. Observe beside the forwarding path

When `isJson` is true:

- create one `createJsonObserver` whose callback stores the observed total in the existing
  `observedUsage` variable;
- register `jsonObserver.observe(chunk)` on the same `src` `"data"` events used by the idle
  watchdog;
- guard the call site so an observer failure cannot reach the forwarding path; detach the
  observer on failure;
- keep `pipeline(src, res, onComplete)` exactly as the non-SSE path has it. Insert no `Transform`
  and no other stream stage into the non-SSE forwarding chain.

The bytes forwarded to the client remain the upstream bytes in the upstream order. Framing,
`content-length` restoration, idle-watchdog behavior, and the legacy disabled-mode path remain
unchanged.

### 3. Reconcile on successful completion

In `onComplete`, for a successful completion (`!error`) with a live reservation:

- end the observer created for this response (`sseObserver.end()` for SSE;
  `jsonObserver.end()` for non-streaming JSON);
- then call `budgetReservation.reconcile(observedUsage)`.

Valid actual usage replaces the estimate in the same global reservation and, when the request
named a configured model, the same model reservation. RPM remains unchanged.

Missing, malformed, or unusable usage delivers `null`; `reconcile(null)` retains the estimate and
records one fallback.

On a mid-stream failure or other abnormal completion, record no outcome and keep the estimate.
Do not reconcile on an error completion.

### 4. Preserve SSE and disabled mode

SSE behavior stays exactly as landed in e04s06. Disabled mode creates no observer, changes no
response, and keeps the original streaming behavior.

## Orchestrator decisions

### D1 — No transform for non-streaming observation

The bounded copy lives beside `pipeline(src, res, onComplete)`. The forwarding chain stays
`src -> res`. This is the regression guard for byte identity, chunk timing, framing, and
`content-length` restoration.

### D2 — Content-type agnostic observation

A usage-bearing body under a mislabeled content type still reconciles. A non-JSON body simply
fails parsing and records one fallback. The response header never decides eligibility.

### D3 — Abnormal completion records no outcome

A successful body completion records exactly one reconciliation outcome. A mid-stream failure,
pre-header failure, or client disconnect records none. Every admitted request still releases its
admission slot exactly once; task 4 proves the abnormal terminals.

### D4 — One observer per response

Create at most one JSON observer per response. `observedUsage` holds its single outcome.

## Tests to add

Add the six tests to the existing `describe("e04s07 non-streaming usage reconciliation")` block in
`server.test.js`.

Required test names:

1. `non-streaming JSON bytes are identical to upstream`
2. `valid non-streaming usage replaces the estimate`
3. `missing non-streaming usage retains the estimate`
4. `malformed non-streaming usage retains the estimate`
5. `higher actual non-streaming usage raises current usage`
6. `non-streaming observation overflow detaches without affecting pass-through`

Required behavior:

1. Upstream returns a non-streaming JSON body. The client receives the exact upstream bytes,
   including content framing relevant to the body. Assert byte identity, not substring equality.
2. Enable a tight global TPM window. The request estimate exceeds half the window. Upstream
   reports `usage.total_tokens` 12. After the first response completes, a second estimated
   request fits the window, proving reconciliation replaced the estimate with 12.
3. Same tight-window setup. Upstream returns JSON without usable usage. After the first response,
   the second request is rejected, proving the estimate remains.
4. Same tight-window setup. Upstream returns JSON with malformed usage. After the first response,
   the second request is rejected, proving the estimate remains.
5. Enable a global TPM window. Upstream reports actual usage above the window limit. The first
   response still reaches the client intact. The following request is rejected, proving actual
   usage raised current usage.
6. Upstream returns a body larger than 1,048,576 bytes. The client receives every byte
   byte-identically. The estimate remains, so a following request under a tight window is
   rejected.

Use the existing hermetic HTTP harness. A suitable request body is:

```js
JSON.stringify({ model: "m", messages: [{ role: "user", content: "hi" }] })
```

Use `PROXY_RPM` and `PROXY_TPM` together, `PROXY_SAFETY_MARGIN_PCT: "0"`, and a TPM value that
separates the estimated cost from the reconciled 12-token cost. The landed SSE tests use a
1,500-token window for this purpose; verify the arithmetic against the actual estimator instead
of assuming it.

For overflow, the upstream body must exceed 1,048,576 bytes and the client-side assertion must
compare the complete received bytes with the complete upstream bytes. Avoid a body that is valid
JSON at the bound; overflow behavior must be independent of parseability.

The existing stub supports arbitrary response bodies through `withProxy({ body, headers })`. Add
stub modes only when a mode materially improves determinism.
