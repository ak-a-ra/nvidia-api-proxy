## Requirements

Task 4 proves existing conservative behavior. No production behavior change is expected.

### 1. Upstream 429 passes through exactly once

An upstream 429 reaches the client with its original status, headers, and body. The proxy makes
exactly one upstream request. It adds no retry, replay, cooldown, backoff, or circuit policy.

A 429 body carries no usable usage. The estimate remains, so a following request under a tight
global TPM window is rejected.

The upstream response must include a non-empty JSON error body and a `Retry-After` header. The
client must receive that body and header unchanged.

### 2. Pre-header failure remains a generic local 502

A stub that destroys the upstream socket before response headers yields:

```json
{ "error": "Bad gateway" }
```

The body contains no DNS name, URL, provider detail, socket text, or upstream host/port. The
proxy process stays healthy.

### 3. Mid-stream non-streaming failure destroys only that response

A JSON response cut after headers/body bytes begin destroys that response stream. The proxy
process stays healthy and can serve a later request normally. The response must not turn into a
local 502 after upstream headers were already delivered.

### 4. Client disconnect commits the estimate without a 502

When the client disconnects during an active upstream response:

- upstream work is cancelled;
- no local 502 body reaches the disconnected client;
- the estimate remains committed;
- a following request under a tight window sees that estimate and is rejected.

Pre-header failure, mid-stream failure, and client disconnect keep the estimate with no counter
movement. They still release admission exactly once through existing response lifecycle handling.

### D4 — Deterministic stub state

Stub modes that need one abnormal response followed by a normal response must be stateful by
request count, so the test can prove the proxy process remains usable without making every later
request abnormal.

## Tests to add

Add the five tests to the existing `describe("e04s07 non-streaming usage reconciliation")` block
in `server.test.js`.

Required test names:

1. `upstream 429 passes through exactly once`
2. `upstream 429 retains the estimate`
3. `pre-header failure remains a generic 502`
4. `mid-stream non-streaming failure destroys only the response`
5. `client disconnect commits the estimate without a 502`

Required behavior:

1. Stub upstream answers 429 with a JSON error body and `Retry-After`. Client receives status 429,
   exact body, and the original `Retry-After`. Stub request count is exactly 1. Wait briefly after
   response completion and re-check count to detect delayed replay.
2. Same 429 setup under a tight global TPM window. First response completes; a following request
   is rejected, proving the estimate remains.
3. Stub destroys the upstream socket before headers. Client receives status 502 and exact generic
   body. Assert response body contains none of the upstream base URL, host, port, or provider
   detail. Assert `/health` remains healthy.
4. Stub sends JSON response bytes, then destroys the upstream socket mid-body. Client observes a
   terminated/incomplete response, not a local 502 body. Assert proxy health remains 200 and a
   later normal upstream request succeeds with its exact body. The stub mode must fail only the
   first request when this proof is needed.
5. Stub sends a response chunk and holds the upstream stream open. Client reads/cancels and
   disconnects. Assert no 502 body is delivered to the disconnected client. Under a tight global
   TPM window, the following request is rejected because the first estimate remains. The stub
   mode must hold only the first request when this proof is needed.

Use existing stub capabilities where deterministic:

- `preabort` already destroys before headers.
- `midabort` always destroys mid-stream.
- `abortable` always holds after one chunk.
- generic `status`, `body`, and `headers` options can create a 429.

Add stateful once-only variants only where a later normal request must prove process health or
behavior.
