## Requirements

### 1. Shared usage validity helper

Export:

```js
usageTotalFromUsage(usage) -> number | null
```

The helper returns a finite, non-negative total for a usable usage object and `null` otherwise.
The usable total is:

- `usage.total_tokens` when it is a finite number greater than or equal to zero; otherwise
- `usage.prompt_tokens + usage.completion_tokens` when both are finite numbers greater than or
  equal to zero.

A missing, null, non-object, or array `usage` is unusable. A non-finite, negative, or non-number
component is unusable. Do not round, clamp, coerce, trim, or normalize values.

`createSseObserver` must keep its current public behavior and must delegate its existing
`isValidUsage` and `usageTotal` checks to `usageTotalFromUsage`. Existing SSE behavior and
outcomes must remain unchanged.

### 2. Bounded JSON observer

Export:

```js
JSON_OBSERVATION_BYTE_BOUND = 1048576
createJsonObserver(onUsage) -> { observe(chunk), end(), detach() }
```

Contract:

- The observer copies raw response bytes for later whole-body JSON parsing. It does not parse
  partial JSON while chunks arrive.
- The running byte total may reach exactly 1,048,576 bytes. A chunk that would push the total
  past 1,048,576 bytes drops the copy and detaches before that chunk is retained.
- The retained copy never exceeds 1,048,576 bytes.
- `observe(chunk)` never throws. It is inert after `end()` or `detach()`.
- `end()` decodes the retained copy once, parses it once as JSON, and invokes `onUsage(total |
  null)` exactly once. It is inert on a second call.
- A valid JSON body whose `usage` object is usable invokes `onUsage(total)`.
- Missing usage, malformed usage, invalid JSON, and an empty body invoke `onUsage(null)`.
- `detach()` drops the retained copy, marks the observer detached, and invokes `onUsage(null)`
  exactly once if no outcome was delivered yet. After detachment, `end()` is inert and cannot
  deliver a second outcome.
- A callback failure must not escape the observer.
- Multi-byte UTF-8 characters split across chunks must decode correctly when `end()` runs.

`createJsonObserver` is new in this task. `createSseObserver` keeps its current lifecycle,
including its current `detach()` and `end()` callback timing.

## Orchestrator decisions

### D1 — One shared definition of usable usage

The two observers must agree on what usable usage means. Extract that rule once as
`usageTotalFromUsage`; do not keep private copies in either observer.

### D2 — Byte accounting uses encoded bytes

The bound applies to raw response bytes, not JavaScript string length. A multi-byte character
counts by its encoded byte length. Check the prospective total before retaining a chunk.

### D3 — Parse once, at completion

A JSON body cannot be parsed incrementally like SSE. Accumulate the bounded raw copy, then parse
it once in `end()`. Do not add partial-JSON parsing, last-fragment heuristics, or a second parse.

### D4 — Observer failure cannot affect forwarding

All observer methods are failure-contained. The later server integration will call these methods
beside the forwarding path, so observation must never throw into that path.
