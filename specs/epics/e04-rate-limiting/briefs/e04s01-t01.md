## Objective

Move configuration parsing out of `server.js` into a root-level `config.js` that exposes
one parse entry point. `server.js` becomes a consumer of that module. No behavior change.

## Requirements

1. `config.js` sits at the project root, next to `server.js`. ESM only (`"type": "module"`
   in `package.json`) — use `import` / `export`, never `require`.
2. It must export exactly one parse entry point. The function takes an `env` object and
   returns the existing config shape, unchanged:
   ```js
   { baseURL, apiKey, proxyToken, unconfigured }
   ```
3. `readSeconds` moves with it. `server.js` currently exports `CONNECT_TIMEOUT_SECONDS` and
   `IDLE_TIMEOUT_SECONDS` as the result of `readSeconds("UPSTREAM_CONNECT_TIMEOUT_SECONDS", 30)`
   and `readSeconds("UPSTREAM_IDLE_TIMEOUT_SECONDS", 120)`. Those two named exports must
   continue to exist on `server.js` with the same names and the same lenient parsing
   semantics (null / empty / whitespace → fallback; non-finite or negative → fallback;
   `0` disables).
4. `server.js` must keep `export default server`. This is the only seam the test suite uses;
   `server.test.js` spawns `server.js` as a child process and never imports it.
5. Environment variables stay read at module import time. Do not add a lazy getter, a
   reload path, or a setter.

## Code that moves

From `server.js` lines 11–38, verbatim in behavior:

- the `validateConfig(env)` function and its comment block (lines 7–38, comment included)
- the `readSeconds(name, fallback)` function and its comment block (lines 52–~62)
- `const config = validateConfig(process.env);` (line 39)

Keep every comment. The comment above `validateConfig` explains the two-regime failure model
and the one above `readSeconds` explains the CONNECT/IDLE split; both are load-bearing for
anyone reading `config.js` alone.

## Must not change

- No dependency added. Node built-ins only (`node:` imports).
- `server.test.js` is not modified. Zero edits. It is the invariant contract.
- `validateConfig` failure regimes are frozen: missing / unparseable / non-http(s)
  `NVIDIA_BASE_URL` stays fatal (`process.exit(1)`); missing `NVIDIA_API_KEY` or
  `PROXY_AUTH_TOKEN` stays a runtime `unconfigured: true` that yields 503, not a crash.
  Whitespace-only counts as missing via `?.trim()`.
- `process.exit(1)` must still fire before anything else in the process observes the bad
  config. If extracting the function makes it importable-but-not-invoked, `server.js` must
  invoke it at import time exactly as it does today.
- No new env var in this task. `PROXY_HOST` arrives in task 2; the operational limits arrive
  in tasks 3–6. Adding them now breaks the task ledger.
- No reformatting, no renaming of unrelated identifiers, no opportunistic cleanup.
