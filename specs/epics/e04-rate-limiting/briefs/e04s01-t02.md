## Objective

Make the proxy's bind address configurable. Today `server.js:237` hardcodes
`server.listen(PORT, "0.0.0.0", ...)`. Read the address from `PROXY_HOST` in the config owner,
defaulting to `0.0.0.0` so the current deployment behavior is unchanged when the variable is
absent.

## Requirements

1. `config.js` owns the read. `PROXY_HOST` is parsed there, not in `server.js`, and is exported
   on the returned config object.
2. Default is the string `0.0.0.0` when `PROXY_HOST` is unset, empty, or whitespace-only. That
   default is what keeps `render.yaml` and the live deploy byte-identical in behavior.
3. `server.js:237` uses the value from the config object instead of the literal.
4. Do **not** validate the host as a URL, do **not** resolve it through DNS, and do **not**
   reject unknown values. A bind address is passed straight to `server.listen`. Rejecting
   unknown values would turn a working deploy into a startup crash for no security benefit —
   `server.listen` already fails loudly on an address it cannot bind, and that failure is a
   runtime one, not a configuration-regime one.
5. Whitespace-only counts as unset, matching the existing `?.trim()` convention in
   `parseConfig`. Do not trim a non-empty value into a different one silently: if you trim,
   say so in a comment.

## The test

Add tests named so that `node --test --test-name-pattern 'PROXY_HOST'` selects them.

**Do not guess the network.** Do not enumerate `os.networkInterfaces()` to find a non-loopback
address to assert against, and do not silently skip the negative half when no such address
exists — that produces a test that passes without testing anything on some hosts.

Instead, make the bound address observable. The test harness already spawns `server.js` as a
child process and reports the port back over IPC (`startProxyServer`, `server.test.js:100`).
The child's init script already calls `server.address()`:

```js
server.on("listening", () => {
  process.send({ port: server.address().port });
});
```

`server.address()` on a listening TCP server also returns the bound `address`. Send that too —
`process.send({ port: server.address().port, address: server.address().address })` — and assert
on `proxy.address`.

This is an **additive** change to the harness. Existing tests read `msg.port` and are
unaffected. Do not restructure `startProxyServer`, do not change `withProxy`, and do not change
any existing assertion.

Cover all three of these:

1. `PROXY_HOST=127.0.0.1` → the reported bound address is `127.0.0.1`, **and** a request to
   `http://127.0.0.1:<port>/health` returns 200. Reuse the existing harness:
   `withProxy(t, { proxyEnv: { PROXY_HOST: "127.0.0.1" } })`. `null` is the "leave unset"
   sentinel in `startProxyServer`; do not pass `undefined`.
2. `PROXY_HOST` unset → the reported bound address is `0.0.0.0`. This is the regression guard
   for the default.
3. Under `PROXY_HOST=127.0.0.1`, the four behaviors the brief must not disturb still hold:
   header forwarding, credential swap (client token accepted, upstream key substituted),
   path mapping, and `/health`. Reuse whatever existing tests already cover these rather than
   writing near-duplicates — the point is that a non-wildcard bind changes none of them.

## Must not change

- No dependency added. Node built-ins only (`node:` imports).
- `config.js`'s existing export keeps its name, `parseConfig`, and its returned shape keeps
  `{ baseURL, apiKey, proxyToken, unconfigured }` — `PROXY_HOST` is **added** to it. The two
  failure regimes stay exactly as they are: `NVIDIA_BASE_URL` problems fatal at startup,
  missing credentials a runtime 503.
- `readSeconds` leniency is untouched. `PROXY_HOST` is not a timeout.
- `server.js` must keep `export default server`.
- `server.test.js`: additive only. Never weaken, delete, reorder, or skip an existing test, and
  never loosen a stub. Adding a field to the IPC payload and adding new tests are the only
  permitted edits.
- No new env var beyond `PROXY_HOST` here. The operational limits arrive in tasks 3-6.
