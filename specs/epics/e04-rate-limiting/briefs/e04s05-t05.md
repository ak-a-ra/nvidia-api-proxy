## Orchestrator decisions (apply these; record any deviation in the report)

### D20 — the ledger's count gate is broken and must be strengthened

The ledger's task-5 verify computes the test count like this:

```bash
N=$(node --test --test-reporter=tap server.test.js 2>&1 | grep -cE '^[[:space:]]*ok [0-9]+ - ')
```

Measured on this tree (2026-10-21): that counts **176** lines, not 161 — the TAP reporter emits one
`ok` line per test (161), one per `describe` block (15), and one for the file (1). The gate then
greps the docs for "176", finds nothing, and fails on a tree where every count is correct.

Take the count from the TAP summary line instead, and make the gate fail on any living doc that
states a different number:

```bash
N=$(node --test --test-reporter=tap server.test.js 2>&1 | grep -E '^# tests [0-9]+$' | grep -oE '[0-9]+')
hits=$(grep -rnE '(^|[^A-Za-z0-9])[0-9]{2,4}[ -]tests?\b|tests-[0-9]{2,4}|\(currently [0-9]+\)' --include='*.md' --include='*.yaml' . | grep -v '^\./plans/' | grep -v 'docs/research/config-invariant-guard-tests' | grep -v '/briefs/' | grep -v '^\./LOG.md' | grep -v '/specs/verifications/' | grep -v -- '-tasks.yaml')
bad=$(printf '%s\n' "$hits" | grep -vE "(^|[^A-Za-z0-9])${N}[ -]tests?\b|tests-${N}\b|\(currently ${N}\)")
printf '%s\n' "$hits"; test -z "$bad"
```

The character class matters: `[^A-Za-z0-9]` before the digits keeps "e04s04 tests" (a story id, not
a count) out of the sweep.

The exclusions, each with a reason:

- `plans/` — historical per-plan numbers.
- `docs/research/config-invariant-guard-tests.md` — a dated historical note.
- `briefs/` — append-only dated records of what a task reported at the time.
- `LOG.md` — the same.
- `*-tasks.yaml` — task ledgers are append-only records; `e01s01-tasks.yaml` even carries a
  deliberately wrong count as a CI fixture.
- `specs/verifications/` — dated evidence of what a past slice measured.

Everything else is in scope, including story specs (`e04s01-...md:345`).

Prove the gate both ways, as the earlier slices did: it must be green on the corrected tree, and it
must produce findings on a tree where one doc still says 141 (a copy of the tree in a temporary
directory, or by changing one doc and changing it back — the working tree must end unchanged).
