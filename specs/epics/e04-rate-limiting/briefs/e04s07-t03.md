## Requirements

### 1. No-body branch records one fallback

Current branch in `server.js`:

```js
if (!upstream.body) {
  res.removeListener("close", onDownstreamClose);
  return res.end();
}
```

When a live `budgetReservation` exists, call `budgetReservation.reconcile(null)` before
`res.end()`. `null` retains the estimate and records exactly one fallback outcome.

Keep the existing close-listener cleanup intact. Create no observer on this path. A no-body
200, 204, 304, and HEAD must release admission exactly once through the existing response-close
lifecycle.

When rate limiting is disabled or no reservation exists, behavior stays unchanged.

### 2. One outcome maximum

`budgetReservation.reconcile(null)` is single-shot. A second reconciliation call records no
additional outcome, and a reconciliation after a fallback is a no-op. The server branch calls it
once; the budget contract prevents duplicates.

## Orchestrator decisions

### D1 — Fallback is the no-body outcome

A no-body response cannot supply actual usage. It records one fallback while retaining the
estimate. It does not create a JSON observer and does not attempt to parse an empty body.

### D2 — Reconcile before ending the response

Call `reconcile(null)` before `res.end()` so the reservation reaches its terminal state before
the client response finishes.

### D3 — Abnormal paths remain unchanged

Task 3 touches only the `!upstream.body` branch. Pre-header failure, mid-stream failure, client
disconnect, and upstream 429 remain for task 4.

## Tests to add

Required test names:

1. `204 no-body response retains the estimate`
2. `304 no-body response retains the estimate`
3. `HEAD no-body response retains the estimate`
4. `empty 200 body retains the estimate`
