## Objective

Read and validate the first strictly-parsed operational pair. `PROXY_RPM` and `PROXY_TPM` are
a **mandatory pair**: both absent or blank means rate limiting stays disabled (behavior
identical to today), exactly one non-blank is fatal at startup, and a non-blank value must be a
positive integer. The values are validated and stored; nothing acts on them yet — acting is
out of scope for this story and belongs to slices #15+.

## Requirements

1. `config.js` owns both reads. `server.js` does no parsing of them.
2. Config shape: add one field to the object `parseConfig` returns.
   `rateLimit: { rpm: <number>, tpm: <number> }` when both are supplied and valid, and
   `rateLimit: null` when the pair is absent or blank. One field, not two, so a caller cannot
   read one half of a pair that was never completed. The existing keys
   `{ baseURL, host, apiKey, proxyToken, unconfigured }` all stay, unchanged.
3. **Exactly one non-blank is fatal.** Exit 1. The stderr message must name **both** variable
   names, so an operator reading only the message knows which pair is incomplete. The story's
   Gherkin says "stderr names the variable"; naming both satisfies that and the partner. Example:
   `PROXY_RPM and PROXY_TPM must be set together: PROXY_TPM is missing`.
4. **A non-blank value must be a positive integer.** `0`, negatives, fractions (`1.5`),
   non-numeric (`abc`), and anything `Number.isSafeInteger` rejects are fatal, each with a
   stderr message naming the offending variable.
5. **The blank check precedes numeric parsing.** `Number("  ")` is `0`, so parse order matters:
   check `?.trim()` first and treat blank as absent. Story §12 calls this out as a failure mode
   (a whitespace value silently disabling a budget) and the Gherkin has a scenario for it using
   `PROXY_RPM=" "` / `PROXY_TPM=" "`.
6. Do **not** touch `readSeconds`. The two existing timeout variables keep their lenient
   fallback — the story puts tightening them out of scope, and task 7's ADR records the
   contrast.
7. Do **not** add any other variable. Tasks 4–6 add the rest.

### Decision to implement: decimal digits only, no `Number()` coercion

`Number("1e3") === 1000`, and `Number("0x10") === 16`. Story §12 requires this story to make
the scientific-notation call explicitly and pin it in a test rather than leaving it to
`Number()`. **Decision: reject.** A supplied value must match `/^[0-9]+$/` after trimming and
must be a safe integer greater than zero. So `1e3`, `0x10`, `+5`, `.5`, `1_000`, `1e400`, and
a 30-digit run are all fatal, each naming the variable.

Rationale to state in a comment: these are budget ceilings. A value silently reinterpreted
through `Number()` is the exact failure the story names — "a budget that appears to exist and
does not". An operator who writes `1000` gets the same policy as one who writes `1e3`, and the
startup crash is loud and one keystroke away from correct. Reversal is cheap if this proves
wrong later: loosen the guard and change the pinned test.

## The tests

Add tests whose **names contain `PROXY_RPM` or `PROXY_TPM`** — the verify command selects on
name pattern, so this is required, not stylistic. Put them in their own `describe` block
(e.g. `describe("rate budget config")`); the pattern matches test names, and the describe title
does not need to match.

Two harness seams already exist and you need no new one:

- `runProxyOnce(envOverrides)` (`server.test.js:166`) spawns `server.js` bare, collects
  `{ code, stderr }`. Use it for every fatal case. It inherits `process.env`, so pass a valid
  `NVIDIA_BASE_URL` (e.g. `https://example.com/v1`) plus `NVIDIA_API_KEY` / `PROXY_AUTH_TOKEN`
  — otherwise the process exits 1 for the wrong reason and the assertion proves nothing about
  the rate pair.
- `withProxy(t, { proxyEnv })` (`server.test.js:140`) starts a stub upstream and a proxy child.
  Use it for the cases that must **start**: both blank → starts and `/health` returns 200.

Cover at minimum:

1. Both absent → startup succeeds, `/health` 200.
2. Both blank (including whitespace-only, e.g. `""` and `"   "`) → startup succeeds,
   `/health` 200. Rate limiting disabled, not zero.
3. Both supplied and valid → startup succeeds, `/health` 200.
4. Only `PROXY_RPM` set → exit 1, stderr names both variables.
5. Only `PROXY_TPM` set → exit 1, stderr names both variables.
6. Non-blank but invalid → exit 1 naming the variable. At least: `0`, `-1`, `1.5`, `abc`, and
   an unsafe integer.
7. **The pinned decision:** `1e3` (and `0x10`) are rejected with exit 1, while the equivalent
   literal `1000` is accepted. This is the test story §12 demands.
